# 六足机器人（高级版）

基于 LUBY 控制器和 STM32F10x 的六足爬行机器人固件。机器人使用 18 个 CDS55xx 串行舵机驱动六条腿，另有 2 个舵机控制头部，通过两路数字障碍信号和一路 ADC 距离信号选择前进、转向、后退及展示动作。

## 硬件概览

| 部件 | 接口或编号 |
| --- | --- |
| 左前腿 | 舵机 ID 10、11、12 |
| 左中腿 | 舵机 ID 13、14、15 |
| 左后腿 | 舵机 ID 16、17、18 |
| 右前腿 | 舵机 ID 1、2、3 |
| 右中腿 | 舵机 ID 4、5、6 |
| 右后腿 | 舵机 ID 7、8、9 |
| 头部 | 舵机 ID 19、20 |
| 左侧数字传感器 | ADC/IO 通道 0 |
| 右侧数字传感器 | ADC/IO 通道 1 |
| 距离传感器 | ADC 通道 7 |

这些编号必须与实际舵机 ID 和接线一致。首次上电前应先使用舵机调试工具设置 ID 和中位，避免机构卡死或舵机过载。

## 行为逻辑

主循环每轮读取一次传感器快照，并据此选择状态：

| 状态 | 数字输入 | ADC7 | 动作 |
| --- | --- | --- | --- |
| 1 | 两侧均无障碍 | 小于 180 | 向前行走 |
| 2 | 左侧触发 | 任意范围 | 后退后右转 |
| 3 | 右侧触发 | 任意范围 | 后退后左转 |
| 4 | 两侧触发 | 任意范围 | 后退 |
| 5 | 两侧均无障碍 | 180–499 | 摇头、后退、下蹲和起立 |
| 6 | 两侧均无障碍 | 不小于 500 | 后退后交替执行展示动作 |

数字输入高低电平所代表的物理状态取决于传感器模块和接线。调试时应先读取原始值确认极性。

## 目录

- `src/main.c`：行为状态机和步态/展示动作。
- `src/UpLib/`：LUBY 控制器外设、CDS55xx 舵机及通信驱动。
- `src/UpLib/STM32Lib/`：STM32F10x 标准外设库和启动文件。
- `prj/UP_EX-Star Demo.uvproj`：Keil MDK 工程文件。

本地的硬件手册、课程资料、安装程序、驱动包、压缩包和编译产物未纳入 Git；它们体积较大，且不是构建固件所必需。

## 构建与烧录

1. 安装支持 STM32F10x 的 Keil MDK（原工程使用旧版 MDK 工程格式）。
2. 用 Keil 打开 `prj/UP_EX-Star Demo.uvproj`。
3. 选择工程中配置的 STM32F10x 目标并执行 Build。
4. 使用配套调试器下载固件。
5. 将机器人架空进行首次动作测试，确认 20 个舵机方向、中位和限位正确后再落地运行。

仓库不提交 `List/`、`Objects/`、`.axf`、`.hex`、`.bin` 等生成文件；本地构建后这些文件会继续被忽略。

## 代码健壮性

当前版本对原始工程做了以下防护：

- 修复 IO 和 PWM 通道检查中的一位越界，以及批量 IO 写入的数组越界。
- ADC DMA 缓冲区声明为 `volatile`，并为数字通道读取增加边界检查。
- 舵机发送队列在 DMA 忙时不切换缓冲区，并拒绝非法长度或空数据指针。
- 串口接收器校验帧长度、队列满状态和环形下标，避免覆盖或越界。
- 同一中断组内同时到达的 EXTI 信号会逐个处理，不再只处理第一路。
- 主状态机每轮只采样一次，避免判断状态变化时二次采样导致执行错误分支。

动作函数仍采用阻塞延时，这是原机械动作序列的设计。部分动作节点会重新采样以便提前退出，但延时和连续舵机指令之间不能实时响应障碍物，因此调试和运行时必须保留安全距离。若用于无人值守或高速环境，应进一步改造成基于定时器的非阻塞动作调度器，并加入急停、欠压和舵机过载保护。

## 修改动作参数

`UP_CDS_SetAngle(id, position, speed)` 中：

- `id` 是舵机编号。
- `position` 通常位于 0–1023，约以 512 为中位。
- `speed` 控制转动速度。

不要直接复制其他机器人的角度。装配公差、舵机零位和安装方向不同，错误参数可能造成碰撞或堵转。建议每次只调整一个关节，并逐步扩大动作范围。
